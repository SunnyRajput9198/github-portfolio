REAL-TIME

WebSockets · Shared Queues

MUSIC

YouTube · Spotify

GITHUB ↗
EXPLORE CASE STUDY ＋
OVERVIEW / PURPOSE

Shared listening rooms let people build a queue and listen to music together.

SOLUTION / KEY FEATURES

Shared spaces, YouTube and Spotify streams, synchronized playback, upvotes, queue promotion, and authentication.

TECHNICAL IMPLEMENTATION

A room-based WebSocket manager broadcasts playback and queue changes. PostgreSQL and Prisma persist queue data; vote-weighted ordering promotes tracks by audience votes.

ARCHITECTURE

Next.js clients connect to room-scoped WebSocket events; PostgreSQL stores persistent queue and voting state through Prisma.

ENGINEERING DECISIONS

Atomic vote-count updates help prevent duplicate or conflicting queue states; playback changes are synchronized across connected room members.

TECH STACK

OVERVIEW / PURPOSE

A single gateway API provides a consistent way to route requests to multiple AI model providers.

SOLUTION / KEY FEATURES

Anthropic, OpenAI, and Gemini provider adapters, JWT and bearer authentication, a real-time monitoring dashboard, and OpenAPI documentation.

TECHNICAL IMPLEMENTATION

A Bun and Elysia.js backend integrates provider SDKs. The React dashboard uses TanStack Query and Elysia Eden for type-safe frontend-to-backend communication.

ARCHITECTURE

React dashboard → typed Elysia Eden client → Bun/Elysia API → provider SDKs, with PostgreSQL for application data.

ENGINEERING DECISIONS

Provider abstraction keeps the client-facing API consistent across model vendors; shared Eden types connect the frontend contract to backend routes.
